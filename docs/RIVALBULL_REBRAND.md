# RivalBull 牛牛牧场改造

状态：已实施，2026-09-28。开发分支：`frontend`；术语见 [CONTEXT.md](../CONTEXT.md)。

## 已确认的设计

- A1：可爱牧场风。A2：职业相关、可爱的 XX牛。A3：前后端专家资料一致。
- Q4：不要全用叠词。采用混合命名，48 个名字唯一，少量保留叠词。
- Q5：扁平绘本风。奶油纸色、草绿、天空蓝和暖黄；牛牛用毛色、服装、眼镜、帽子及职业道具区分。
- 董事长固定为 L3-001 钟钟牛；其他 ID、专业职责、技能和知识标签延续。当前访问者称“牧场访客”。
- Q6：按推荐。默认自动分工：MiMo-V2.6-Pro 核心分析，MiMo-V2.6-Flash 辅助/杂务；可手动选择任一模型用于整个新任务。
- UltraSpeed 当前未启用，菜单禁用；不会自动改用其他服务地址或密钥。后端按配置校验可选模型，Trace 始终展示实际调用 ID。

## 数据与调用链

`branding/experts.json` 是专家资料的单一编辑源。运行 `python scripts/generate-brand.py`，生成 48 张本地 SVG 牛牛头像，并同步前端 public、backend、api 三份运行名册与头像索引。之后运行浏览器测试检查一致性。

专家 JSON 在后端进程中缓存。后续修改名册并同步到运行 worktree 后，使用根目录 `stop.bat`、`start.bat` 重启服务，使新资料立即生效。

浏览器模型菜单 → GET `/api/models` → POST `/api/tasks` 的 `model` → 任务澄清 JSON 的 `_model` → 澄清阶段与 SSE 编排 → 每个真实 LLM 请求。自动分工保留 tier 选择；手动模式覆盖 core/aux/fast、舆情分析及流式调用。报告保存 `model_selection`，章节深化延续选择。上下文按异步任务隔离，不修改进程全局模型；模型选择不会因澄清答案而被覆盖。

后端 `/api/experts`、`/api/experts/workload` 与浏览器离线回退使用相同姓名和本地头像路径。原名册内的预填任务量归零，在线任务量读取数据库。

## 历史兼容边界

- 保留既有 SQLite 数据库文件 `app/data/verda.db`、`VERDA_DB_PATH` 环境变量和浏览器 `verda.annotations.v1` / `verda.knowledge.v1` 存储键。这些是兼容标识，不是当前产品名。
- 不清空、不重写用户数据库、报告正文、证据、批注和收藏。身份组件按原有专家 ID 查询新资料。历史 Trace 的提示词和响应保留原始记录。
- 原版研究文档与许可证保留出处；不把真实被研究品牌或引用来源替换成牛牛名字。
- 前端分支包含配套 backend/api 改动，可形成一个完整提交。运行用 backend worktree 和 api worktree 的对应文件已同步，已有密钥与 MiMo 适配保留。
- 根目录启动脚本兼容 RivalBull 健康标识；不改变端口，前端 3400，后端 8010。

## 验证

在 `frontend/` 运行 `npm run lint`、`npm run build`、`npm run test:ui`。浏览器验证需要 Chrome，可在 playwright.config.ts 修改 channel 使用已安装的 Chromium。

在 `backend/` 使用已安装依赖的 Python 运行 `python -m unittest discover -s tests -v`。

- 后端 12 项测试覆盖 MiMo 请求参数、配置兼容、模型白名单、选择持久化、澄清保护、并发隔离、流关闭/异常清理、章节深化。
- 浏览器检查覆盖 48 身份和 3 份运行名册、所有头像加载、11 个页面入口、模型请求参数、故障/离线回退、历史本地数据、CSV 与打印、桌面/手机布局。
- 浏览器调研采用隔离接口夹具，验证不会产生付费模型请求或写入用户数据库。真实本地服务另行检查健康、模型列表与专家接口。
- 本轮结果：lint、生产构建、12 项后端测试、8 项浏览器测试通过；真实本地接口的 48 位身份/职业/头像与 workload 一致，模型列表为自动分工/Pro/Flash，UltraSpeed 禁用。已重启服务并确认首页和牧场无浏览器运行错误。
